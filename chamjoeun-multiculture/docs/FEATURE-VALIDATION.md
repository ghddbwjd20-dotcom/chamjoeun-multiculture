# 남은 기능 검증 및 관리자 운영 안내

외부 서비스 키 없이 확인할 때는 별도 로컬 PostgreSQL과 로컬 웹 서버를 사용합니다. 운영 배포 전 DB에 `010_certificate_stamp.sql`까지 적용합니다.

## 로컬 검증

1. 로컬 DB 연결 주소를 준비하고 `node --env-file=<로컬 환경파일> --experimental-strip-types scripts/migrate.ts`를 실행합니다. `APP_URL`은 실제 개발 서버 주소와 맞춥니다.
2. `DEV_EMAIL_PREVIEW=true`, `NOTIFICATION_SENDING_ENABLED=false`를 설정합니다. 회원가입이나 비밀번호 재설정 폼에서 표시되는 개발 링크를 열어 실제 메일 없이 흐름을 확인합니다.
3. 12자 이상 `DEV_ADMIN_PASSWORD`와 로컬 DB 연결 주소로 `npm run db:seed:dev`를 실행합니다. 기존 개발 샘플에 영상이 필요하면 같은 로컬 환경으로 `scripts/prepare-preview-content.ts`를 실행합니다.
4. 과정 신청 후 **나의 강의실 → 내 알림**에서 수강 안내를 확인합니다. 학습을 진행한 뒤 **관리자 → 회원·수강**에서 과정과 회원으로 검색해 인정 시청시간과 진도율을 비교합니다. 수동 수료 사유, 관리자, 처리 시각도 확인합니다.
5. **관리자 → 알림·발송**에서 뉴스레터 초안을 저장하고 수신 동의·인증 회원을 선택해 예약합니다. 수신 대상과 상태는 발송 이력에서 확인합니다. 이메일 찾기는 이름과 등록 전화번호가 유일하게 일치할 때만 일부 가린 이메일을 SMS 작업에 넣습니다. 등록 번호를 사용할 수 없는 회원은 문의로 안내합니다.
6. **관리자 → 발급문서**에서 증서 제목·발급기관·문구와 PNG 직인을 등록합니다. 수료증은 수료한 회원이, 자격증은 관리자가 발급합니다. 문서 번호와 발급 당시 양식·직인은 발급본에 저장됩니다. 실제 양식을 확인할 때는 테스트 DB에서 일반 과정을 만들어 사용합니다. 개발 샘플 수료증에는 개발 확인용 표시가 들어갑니다.
7. **관리자 → 문의**에서 답변을 저장합니다. 이메일 발송 예약을 선택한 경우 발송 이력에서 해당 작업을 확인합니다. 회원은 마이페이지의 내 문의에서도 답변을 볼 수 있습니다.

## 외부 연결 후 확인

- **메일·소셜 로그인**은 환경 키와 발신 도메인, 콜백 URL을 입력하고 가입·이메일 인증·비밀번호 복구를 확인합니다. 소셜 계정은 기존 이메일과 일치해도 자동 병합하지 않습니다. 기존 계정에 로그인한 뒤 마이페이지에서 연결합니다.
- **결제**는 토스 테스트 키로 결제 성공·실패·전체 취소와 수강권 변화를 확인합니다. 운영 키는 상점 심사 후 교체합니다.
- **영상**은 R2/S3, 재생 Worker, FFmpeg 작업자를 연결합니다. 업로드 진행률 → HLS 변환·썸네일 → 수강권 재생 → 이어보기 → 재처리 순으로 확인합니다. 파일 삭제는 테스트 영상으로 확인합니다. 영상 파일 삭제가 일부 실패하면 차시 노출은 중지된 상태로 유지되며, 같은 삭제 버튼으로 나머지 파일 삭제를 재시도할 수 있습니다.
- **자동 발송**은 가입 인증 완료, 무료 신청, 유료 결제 완료, 자동·수동 수료에서 사이트 알림을 기록합니다. 이메일과 구독 브라우저 알림은 발송 대기열에 넣습니다. SMS/알림톡은 `NOTIFY_*_CHANNEL`에 이벤트별 `sms` 또는 `alimtalk`를 지정합니다. 알림톡은 이벤트별 승인 템플릿을 `SOLAPI_TEMPLATE_*`에 지정하고 `#{제목}`, `#{안내}` 변수를 맞춥니다. 관리자의 수동 알림톡은 `SOLAPI_ALIMTALK_TEMPLATE_ID`를 사용합니다. 발송 시점과 문구는 운영 협의 후 확정합니다.
- **푸시**는 VAPID 공개키·비밀키·연락처를 설정한 뒤 HTTPS 환경에서 로그인하고 **내 알림**의 브라우저 알림을 허용합니다. 수신과 해제를 지원하는 브라우저에서 각각 확인합니다.
- **발송 작업자**는 `npm run worker:delivery`로 실행합니다. 외부 발송을 켜기 전에 대기열의 대상과 내용을 확인합니다. **관리자 → 연동 상태**에서 키 입력 여부와 작업자의 최근 실행 시각을 확인할 수 있습니다. 발송 접수는 제공업체 접수이며 실제 수신 여부는 제공업체 내역과 수신 기기에서 확인합니다.
- **운영 백업**은 PostgreSQL 클라이언트 도구가 설치된 서버에서 `BACKUP_DATABASE_URL`(직결 주소)과 `BACKUP_DIR`(운영 DB와 분리된 저장 공간)을 설정합니다. 서버 스케줄러에서 `npm run db:backup:production`을 매일 1회 실행합니다. Linux cron 예시는 `0 18 * * * cd /srv/chamjoeun-multiculture && npm run db:backup:production`입니다. 서버 시간이 UTC일 때 한국시간 오전 3시에 실행합니다. 검증된 덤프가 저장된 후 UTC 날짜 기준으로 최근 7일 보관을 적용합니다. 운영 전 별도 DB에 복원해 확인합니다.
- 운영 오픈 전에 정식 도메인, 실제 교육과정·영상, 승인된 증서 양식으로 전체 검수합니다. 모바일·키보드·화면 낭독기 확인과 관리자 온라인 교육 1회는 운영 인수인계에서 진행합니다.

## Vercel에서 웹을 운영할 때 작업자 실행

Linux Docker 서버에서 deploy/workers.env.example을 프로젝트 루트의 .env.workers로 복사하고 실제 값을 설정합니다. Vercel과 같은 외부 PostgreSQL을 사용합니다. 영상 작업 볼륨은 최대 원본 크기의 5배에 2GB를 더한 여유 공간을 확보합니다.

```sh
docker compose -f deploy/compose.workers.yml --profile video up -d --build
docker compose -f deploy/compose.workers.yml --profile delivery up -d --build
```

발송은 공급자 설정을 마친 뒤 .env.workers에서 NOTIFICATION_SENDING_ENABLED=true를 설정해야 실행됩니다. 키와 URL은 Vercel과 작업자 환경에 필요한 항목을 각각 등록합니다. 운영 DB의 마이그레이션을 먼저 적용하고 관리자 연동 상태에서 작업자 실행을 확인합니다.
